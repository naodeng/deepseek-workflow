Chat with [DeepSeek](https://www.deepseek.com/) straight from Alfred — a fork of the [Alfred OpenAI Workflow](https://github.com/alfredapp/openai-workflow) that talks to the [DeepSeek API](https://api-docs.deepseek.com/) (OpenAI-compatible) instead of OpenAI.

## Setup

1. Create a DeepSeek account and [log in](https://platform.deepseek.com/).
2. On the [API keys page](https://platform.deepseek.com/api_keys), click `Create new API key`.
3. Name your new API key and click `Create`.
4. Copy your API key and add it to the [Workflow's Configuration](https://www.alfredapp.com/help/workflows/user-configuration/).

## Usage

### DeepSeek Chat

Query DeepSeek via the `deepseek` keyword, the [Universal Action](https://www.alfredapp.com/help/features/universal-actions/), or the [Fallback Search](https://www.alfredapp.com/help/features/default-results/fallback-searches/).

Type `deepseek` followed by your question:

* <kbd>↩&#xFE0E;</kbd> Ask a new question.
* <kbd>⌘</kbd><kbd>↩&#xFE0E;</kbd> Clear and start new chat.
* <kbd>⌥</kbd><kbd>↩&#xFE0E;</kbd> Copy last answer.
* <kbd>⌃</kbd><kbd>↩&#xFE0E;</kbd> Copy full chat.
* <kbd>⇧</kbd><kbd>↩&#xFE0E;</kbd> Stop generating answer.

Answers stream into the Alfred text view as they are generated, and each conversation is kept in `chat.json` under the workflow's data folder.

#### Chat History

View Chat History with <kbd>⌥</kbd><kbd>↩&#xFE0E;</kbd> in the `deepseek` keyword. Each result shows the first question as the title and the last as the subtitle.

<kbd>↩&#xFE0E;</kbd> to archive the current chat and load the selected one. Older chats can be trashed with the `Delete` [Universal Action](https://www.alfredapp.com/help/features/universal-actions/). Select multiple chats with the [File Buffer](https://www.alfredapp.com/help/features/file-search/#file-buffer).

### Models

The workflow supports the two public DeepSeek models:

| Configuration label | Model ID | Notes |
| --- | --- | --- |
| DeepSeek Chat | `deepseek-chat` | General-purpose chat model (DeepSeek-V3). Default. |
| DeepSeek Reasoner | `deepseek-reasoner` | Reasoning model (DeepSeek-R1). Its thinking trace is streamed via `reasoning_content` and appears in the transcript. |

You can also override the model at runtime by setting `deepseek_model_override` (e.g. to point at a custom `deepseek-*` deployment).

## Configuration

| Variable | Default | Description |
| --- | --- | --- |
| `deepseek_api_key` | — | Your DeepSeek API key (required). |
| `deepseek_keyword` | `deepseek` | Keyword used to start a chat. |
| `deepseek_history_save` | on | Save the current chat when starting a new one. |
| `deepseek_model` | `deepseek-chat` | Model used for chat completions. |
| `max_context` | 24 | How many older questions and answers to send. |
| `timeout_seconds` | 10 | Seconds to wait before giving up a stalled connection. |
| `system_prompt` | — | Initial message to guide DeepSeek on the answers you expect. |
| `deepseek_api_endpoint` | `https://api.deepseek.com/v1/chat/completions` | API endpoint; any OpenAI-compatible endpoint can be used (e.g. a proxy). |
| `deepseek_model_override` | — | Optional runtime model override. |

## Notes

* DeepSeek's API is OpenAI-compatible; this workflow only calls the chat completions endpoint. The original workflow's DALL·E image generation flow is not included because DeepSeek does not offer an image generation API.
* DeepSeek requires no organisation header — the OpenAI-Organization header was removed.

## Development

The workflow's `info.plist` is generated from the upstream [alfredapp/openai-workflow](https://github.com/alfredapp/openai-workflow) plist by [`tools/build_info_plist.py`](tools/build_info_plist.py); the icon is generated by [`tools/make_icon.py`](tools/make_icon.py).

To rebuild:

```bash
python3 tools/build_info_plist.py /path/to/openai-workflow/Workflow/info.plist
python3 tools/make_icon.py
```

### Releases

Pushing a tag matching `v*` (e.g. `v1.0.0`) triggers the [release workflow](.github/workflows/release.yml): it syncs the version into `Workflow/info.plist`, packages `DeepSeek.alfredworkflow`, and attaches it to a GitHub Release. You can also run the workflow manually from the **Actions** tab (`workflow_dispatch`) with an optional version input.

```bash
git tag v1.0.0 && git push origin v1.0.0
```
